## دامنه و تغییرات

فقط مرحلهٔ ۲، ثبت‌نام دعوتی و داشبورد دعوت‌ها، پیاده‌سازی شد؛ مراحل دیگر آغاز نشدند. حساب‌های قدیمی لینک شخصی می‌گیرند اما دعوت‌کنندهٔ ساختگی برایشان ثبت نمی‌شود. حساب جدید فقط از لینک فعال ثبت‌نام می‌کند و تراکنش، حساب، رزومه، رابطهٔ دعوت و لینک شخصی را می‌سازد. دعوت اشتراک، پرداخت، پاداش یا فضای اضافه نمی‌دهد.

- مدل‌های لینک دعوت و رابطهٔ دعوت با توکن تصادفی، یکتایی لینک، یکتایی حساب دعوت‌شده، مالکیت ثابت لینک و رابطهٔ غیرقابل‌تغییر.
- مهاجرت `0004` برای ایجاد لینک یکتا برای همهٔ حساب‌های موجود، بدون افزودن رابطهٔ دعوت جعلی.
- ثبت‌نام دعوتی اتمیک و چندبارمصرف؛ لینک نامعتبر یا غیرفعال رد می‌شود و غیرفعال‌سازی هم‌زمان با ثبت‌نام نادیده گرفته نمی‌شود.
- داشبورد لینک قابل کپی، تعداد و نام نمایشی دعوت‌شدگان را نشان می‌دهد و ایمیل آنها را افشا نمی‌کند؛ لینک غیرفعال در داشبورد ارائه نمی‌شود.
- مدیر می‌تواند روابط را بررسی و لینک‌ها را غیرفعال کند؛ برای دعوت گروه اولیه، مدیر لینک حساب خود را از داشبورد به اشتراک می‌گذارد.
- ثبت‌نام موجود با حساب فعال به داشبورد هدایت می‌شود و رابطهٔ دعوت جدید نمی‌سازد. CSRF ثبت‌نام حفظ شده است.
- راهنمای محصول/معماری و CI برای معیارهای جدید به‌روز شدند.

## آزمون‌ها و بررسی‌ها

همهٔ آزمون‌ها با Python محیط `.venv` اجرا شدند. هر دو smoke اسکریپت پایگاه‌دادهٔ موقت و دادهٔ ساختگی مستقل ساختند؛ دادهٔ واقعی و رسانهٔ واقعی پروژه استفاده یا تغییر داده نشد.

| فرمان/بررسی | نتیجه | کد خروج |
|---|---|---:|
| `.\.venv\Scripts\python.exe manage.py check` | بدون خطای بررسی Django | ۰ |
| `.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run` | تغییر مدلِ ثبت‌نشده یافت نشد | ۰ |
| `.\.venv\Scripts\python.exe manage.py test` | ۵۲ آزمون موفق | ۰ |
| `.\.venv\Scripts\python.exe scripts\invitation_concurrency_smoke.py` | دو ثبت‌نام هم‌زمان موفق؛ تعداد موجودیت‌ها صحیح | ۰ |
| `.\.venv\Scripts\python.exe scripts\invitation_migration_smoke.py` | حفظ داده‌های ساختگی قدیمی و ایجاد لینک بدون رابطهٔ جعلی | ۰ |
| `.\.venv\Scripts\python.exe scripts\concurrency_smoke.py` | کنترل هم‌زمان سهمیهٔ بارگذاری موجود همچنان موفق | ۰ |
| `git diff --check` | خطای whitespace یافت نشد | ۰ |

اجرای نخست `manage.py` با Python سیستمی به‌علت نبود Django اجرا نشد؛ همان بررسی‌ها بلافاصله با Python نصب‌شده در `.venv` اجرا و موفق شدند. فایل‌های دادهٔ موقت در `%TEMP%` ساخته و پس از اجرا پاک شدند.

## موارد اجرا‌نشده و محدودیت‌ها

- CI روی GitHub اجرا نشده است؛ هنوز شاخه push نشده و PR وجود ندارد.
- هیچ سرویس بیرونی یا VPS/دامنه‌ای provision نشده و اتصال عملیاتی به پیامک، ایمیل یا پرداخت برای این مرحله لازم نیست.

- آزمون رقابت در SQLite فایل‌محور انجام شد؛ آزمون Django با SQLite حافظه‌اشتراکی در تلاش قبلی به قفل جدول خورد، بنابراین به‌عنوان آزمون نهایی concurrency استفاده نشد.
- لاگ مستقل نگه‌داری نشد؛ شواهد بالا از خروجی موفق فرمان‌ها و آزمون‌های ذخیره‌شده در مخزن هستند.

- مرجع دامنه: تعریف و چک‌لیست مصوب در PR باز [#11](https://github.com/amirfassadi/PerformingArtsCV/pull/11)، شاخه `codex/mvp-invitation-plan`، commit `eeef41c32638a25529607fd20728799d011a82e2`.

این گزارش فقط وضعیت همان commit مبنا را ثبت می‌کند. هیچ قابلیت محصولی در این مرحله پیاده‌سازی نشده است. فایل‌های `docs/MVP.md`، `docs/MVP-TASKS.md`، `docs/BACKEND_IMPLEMENTATION.md`، `docs/FRONTEND_REVIEW.md` و `docs/VPS_PREPARATION.md` در `main` وجود ندارند؛ دامنه ارزیابی از نسخه مصوب PR #11 و شواهد کد گرفته شده است. وضعیت باز بودن یک مرحله به‌تنهایی دلیل نبود قابلیت نیست؛ جدول زیر بر کد و آزمون‌های قابل مشاهده تکیه دارد.

## جمع‌بندی

نسخه مبنا هسته قابل‌آزمونی برای ساخت رزومه، انتشار محدود به مشترکان، رسانه خصوصی، سهمیه مستقل، اشتراک‌ها و پرداخت دارد. اما برای MVP دعوتی آماده نیست:

1. ثبت‌نام بدون دعوت باز است و مدل، اعتبارسنجی، انتساب دعوت‌کننده و مدیریت دعوت وجود ندارد؛ مانع شروع آزمایش دعوتی و موضوع #4.
2. بازیابی رمز و ارسال ایمیل پیکربندی نشده‌اند. محدودیت تلاش، مسیر پشتیبانی، گزارش محتوا و درخواست حذف حساب نیز در محصول دیده نشدند؛ موضوع #8.
3. پرداخت واقعی، سرویس ایمیل، دامنه، سرور و مقصد دوم بکاپ تنظیم یا متصل نشده‌اند. کد پرداخت و بکاپ محلی، اتصال عملیاتی این سرویس‌ها را ثابت نمی‌کنند.
4. آزمون مرورگر اجرا نشد؛ بنابراین مسیر کامل و واکنش‌گرایی موبایل در این ممیزی تأیید نشده است. پذیرش انتهابه‌انتها و شروع آزمایش (#10) قابل اعلام نیست.

آزمون‌های خودکار سرور و رقابت سهمیه موفق بودند. یک snapshot شامل حساب و فایل ساختگی نیز در مسیر موقت ساخته، بررسی و بازیابی شد. این نتایج آمادگی کد پایه را نشان می‌دهند، نه آمادگی تولید یا دسترسی سرویس‌های زنده.

## اعتبارسنجی همین ممیزی

محیط اجرا `.venv` موجود مخزن، Python 3.14.7، Django 5.2.19 و Waitress 3.0.2 بود. `pip check` بدون وابستگی شکسته تمام شد. برای بررسی‌ها `DATA_ROOT` و `PRIVATE_MEDIA_ROOT` به مسیرهای موقت بیرون مخزن اشاره می‌کردند؛ پایگاه داده و رسانه معمول پروژه خوانده یا تغییر داده نشدند. شناسه پذیرندگی خالی و sandbox روشن بود.

| بررسی | نتیجه واقعی |
|---|---|
| `python manage.py check` | موفق؛ بدون مسئله |
| `python manage.py makemigrations --check --dry-run` | موفق؛ `No changes detected` |
| `python manage.py test --verbosity 1` | موفق؛ ۴۳ آزمون، همگی قبول |
| `python scripts/concurrency_smoke.py` | موفق؛ از دو بارگذاری هم‌زمان فقط یکی ذخیره شد و فایل اضافه باقی نماند |
| ساخت و بررسی بکاپ | موفق؛ پایگاه داده موقت با یک حساب، یک پروفایل و یک فایل ساختگی snapshot شد؛ `verify_backup` گذشت |
| بازیابی نمونه | موفق؛ snapshot در `DATA_ROOT` جدا کپی شد، `manage.py check` گذشت و یک پروفایل و فایل ۶۸ بایتی با محتوای اصلی تأیید شدند |
| `python scripts/browser_smoke.py` | اجرا نشد؛ `ModuleNotFoundError: No module named 'playwright'` |
| نصب `requirements-dev.txt` | ناموفق؛ pip خطای `Missing dependencies for SOCKS support` داد؛ آزمون مرورگر پس از آن همچنان اجرا نشد |
| `DJANGO_DEBUG=0 python manage.py check --deploy` | کد خروج صفر؛ دو هشدار باقی ماند: `security.W005` (HSTS شامل زیردامنه‌ها نیست) و `security.W021` (HSTS preload فعال نیست) |

برای بررسی deploy از کلید موقت ساختگی، میزبان‌های localhost، پذیرندگی خالی و sandbox استفاده شد؛ نتیجه، بررسی تنظیمات است و جای استقرار HTTPS را نمی‌گیرد. آزمون‌های درگاه در suite خودکار mock هستند. هیچ درخواست پرداخت یا ایمیل زنده‌ای ارسال نشد. نصب Playwright و اجرای مرورگر نیازمند رفع دسترسی وابستگی SOCKS/شبکه و فراهم‌بودن مرورگر است.

## حفظ کاربران فعلی در مهاجرت دعوتی

این commit هیچ مهاجرت دعوتی ندارد و برای نوشتن این پیشنهاد به پایگاه داده یا رسانه کاربران دسترسی گرفته نشد. مسیر کم‌خطر برای مرحله #4:

1. پیش از هر تغییر، snapshot سازگار پایگاه داده و تمام رسانه‌های ارجاع‌شده بگیرید؛ صحت آن را بررسی کنید و نسخه اصلی را تا پایان آزمون نگه دارید.
2. مهاجرت افزایشی بسازید: حساب، شناسه، hash رمز، پروفایل، اشتراک، پرداخت، منتخب‌ها و فایل‌های موجود حفظ شوند. به حساب‌های قدیمی دعوت‌کننده ساختگی نسبت ندهید؛ رابطه دعوت برای آن‌ها می‌تواند خالی/«قدیمی» بماند.
3. برای حساب‌های موجود لینک دعوت اختصاصی بسازید، بی‌آنکه بازدید از لینک، ثبت‌نام قبلی را به دعوت‌کننده منتسب کند. کاربران قبلی بتوانند وارد شوند؛ فقط ثبت‌نام جدید به دعوت معتبر و فعال نیاز داشته باشد. کاربران آغازین را مدیر از راه دعوت وارد کند.
4. مهاجرت را روی کپی داده آزمایش کنید: تعداد حساب‌ها و پروفایل‌ها، شناسه‌ها، دسترسی‌ها و ارجاع فایل‌ها را قبل/بعد تطبیق دهید؛ rollback و بازیابی را نیز بررسی کنید. داده واقعی را برای این ممیزی استخراج یا ثبت نکنید.

این راهبرد پیشنهاد است، نه تغییر مدل یا اجرای مهاجرت در این شاخه.
